# 神圣奶蛙 · Naiwa Run

仿 Chrome 小恐龙的奶蛙主题跑酷小游戏。**单文件 HTML5，零依赖，双击即玩。**

`index.html` 把全部贴图以 base64 内嵌，脱离任何外部资源都能独立运行，断网也行。

---

## 玩法

跳过迎面而来的狗子和奶瓶。半空中的飞狗分两种：

| 障碍 | 应对 |
|---|---|
| 低飞狗 | 跳过去 **或** 蹲下躲 |
| **高飞狗** | **跳不过去，只能蹲下从底下钻过去** |

- 起速偏慢（5 px/帧），分数越高滚得越快，封顶 16
- 障碍间距随滚动速度自动缩放，连排组合的出现概率随分数阶梯上升（10% → 72%）
- 约每 700 分昼夜交替一次
- 每局成绩自动记进**本地数据库**，点开始页的「🏆 本地排行榜」看 Top 10

## 本地数据库

不依赖任何后端，纯前端持久化，用的是浏览器自带的两种存储：

| 后端 | 何时使用 | 说明 |
|---|---|---|
| **IndexedDB** | 通过 `http(s)` 打开 | 真正的浏览器数据库，带索引 |
| `localStorage` | 通过 `file://` 双击打开 | 降级方案 |

之所以要降级：Chrome/Edge 在 `file://` 下把页面当作 opaque origin，会禁用 IndexedDB。
而本作主打「双击即玩」，所以必须能在两种环境下都正常记录。

排行榜面板的副标题会写明当前用的是哪个后端，打开即可核对。

> 数据存在**本机浏览器**里，换设备/换浏览器不会同步，清浏览器数据会丢失。

## 全网排行榜（可选，默认关闭）

排行榜面板有「本机 / 全网」两个页签。**全网榜默认关闭**，配置留空时就是纯本地模式，
不联网、不报错、功能照旧。

### 怎么开启

全网榜走的是 [TinyWebDB](https://tinywebdb.appinventor.space)（给 App Inventor 社区用的
免费网络微数据库）。它返回 `Access-Control-Allow-Origin: *`，所以 **GitHub Pages 甚至
`file://` 都能直接读写，不需要任何后端代码** —— 这正是「纯前端联机」可行的原因。

1. 去 <https://tinywebdb.appinventor.space> 申请一个库（免费，可申请多个），拿到 `user` / `secret`
2. 填进 `make_dino_game.py` 顶部的 `REMOTE`：

```python
const REMOTE = {
  url:    'https://tinywebdb.appinventor.space/api',
  user:   '',        # ← 填这里
  secret: '',        # ← 填这里
  prefix: 'hnw_',    # 命名空间前缀，改成你自己的，别蹭别人的
  ...
}
```

3. 重新生成：`python make_dino_game.py`

### 记录格式与校验（让瞎写的记录进不来）

一条记录不是「昵称 + 分数」，而是**必须自洽**的一组字段：

```json
{ "v": 3, "n": "昵称", "s": 1234, "f": 5678, "t": 1791800000000,
  "o": "https://你的域名", "c": "1a2b3c4d" }
```

| 字段 | 含义 |
|---|---|
| `v` | 格式版本 |
| `n` | 昵称 |
| `s` | 分数（整数） |
| `f` | **计分帧数**（整数） |
| `t` | 提交时间戳（ms，整数） |
| `o` | **提交来源**（`location.origin`） |
| `c` | 校验码（对上述字段 + 盐值算 FNV-1a） |

读端逐条校验，任一不过就剔除、不显示：

1. 字段齐全、类型正确、版本已知
2. 帧数在合理区间、时间戳在合理区间
3. **来源在允许范围内**（见下）
4. 校验码匹配
5. **分数必须能由帧数精确复现** ← 核心

第 4 条是关键。本作的分数**完全由计分帧数决定** —— 全代码只有一处 `score` 修改点：

```js
score += 0.18 + speed * 0.002;
speed  = Math.min(16, 5 + score * 0.0011);
```

没有随机、没有道具加成。所以给定 `f`，`s` 是唯一确定的。于是「分数 ↔ 帧数」
构成一条**物理不变量**：随便填的分数必然对不上。

举个例子，直接 POST 一条 `{"n":"我","s":999999}`：

- 缺 `v`/`f`/`t`/`c` → 版本不符，剔除
- 补齐字段并算对校验码 `c`，但 `f` 随便填 → **分数与帧数不自洽**，剔除
- 想让分数对得上，就得反推出正确的 `f` —— 也就是必须真的把游戏跑那么多帧

排行榜面板会显示「已剔除 N 条不自洽记录」，可以直接看到它在工作。

### 来源（域名）限制

记录里带 `o` = 提交时的 `location.origin`，读端会校验它。规则：

- **`file://` / `null` / 空来源一律禁止** —— 本地打开的文件不支持联机
  （用户明确要求：不需要 file 能联机）。这样"下载一份本地跑、往榜单灌数据"就不成立。
- `REMOTE.origins` 留空 → 放行所有 http(s) 来源
- `REMOTE.origins` 填了 → **只认名单内的来源**（推荐部署后填自己的正式域名）

```python
origins: ['https://你的用户名.github.io'],
```

> ⚠️ GitHub Pages 的**项目页**共用 `<user>.github.io` 这一个 origin，
> 所以同一账号下的其它项目也会落在白名单里。要更精确得连 `pathname` 一起判。

⚠️ 和校验码一样，**这是策略执行，不是安全边界** —— 白名单同样在源码里，改掉即可绕过。
它的价值是挡住"随手下载一份本地跑"这类**无主观恶意**的情况。

### ⚠️ 安全边界（务必先读）

**前端没有可信身份，`user`/`secret` 也一定能从源码里还原出来**（合成大奶蛙的做了 XOR 混淆，
几秒就能解开）。所以它**防不住恶意用户** —— 任何人都能直接 POST 一个 999999。

这里靠的是**设计**而不是保密：

| 措施 | 作用 |
|---|---|
| **记录自洽校验**（见上） | 分数必须能由帧数复现 → 瞎填的分数进不来 |
| **滚动时间窗**：只展示最近 20 条提交 | 不是历史最高分榜 → 卡榜首没意义，也天然避开并发写冲突 |
| 每人只写自己那条，**全程没有 delete** | 谁都删不掉别人的记录 |
| 提交限频 3 秒 / 分数与帧数范围校验 | 挡住手抖和明显离谱的值 |
| 读取时最多校验 60 条 | 防「灌垃圾记录拖慢读取」 |
| 昵称清洗 + 全部 `textContent` 渲染 | 防 XSS（昵称是用户输入） |
| 读取失败只影响排行榜 | 网络问题绝不阻断游戏 |

**但校验码和公式都在源码里** —— 有心人照着实现一遍就能造出合法记录
（只是他必须真的把游戏跑够帧数，或者自己复现一遍计分公式）。
所以这仍然**只是提高作弊成本，不是防住作弊**。

**真要防住必须有服务端校验分数，那就不是纯静态托管了。**

另外 TinyWebDB 是**免费公益服务，没有 SLA**，可能慢、可能挂。所以本机库始终写入，
联网只是额外同步一份。

## 文件结构

```
index.html                  游戏本体（由生成器产出，可直接双击运行）
make_dino_game.py          生成器：读 art/ 里的 webp → base64 → 产出 index.html
art/                       本作实际用到的 15 张贴图（随仓库提交）
  douluo/                    角色与敌兵，取自「奶斗罗」
  bignaiwa/                  开始页图标，取自「合成大奶蛙」
fetch_assets.py            素材抓取脚本（递归镜像各站点的图片/音频/字体/模型）
dedupe_assets.py           素材内容去重 + 清理误抓的假响应
make_manifest.py           素材清单页生成器
milkyfrog-source-map.html  22 个奶蛙小游戏的源码地图调研报告
```

## 运行

游戏本体不需要构建：

```bash
# 直接双击 index.html 即可；或起个静态服务
python -m http.server 8080
```

改动 `make_dino_game.py` 后重新生成：

```bash
python make_dino_game.py     # → index.html
```

因为素材已随仓库放在 `art/`，**干净检出后无需任何额外步骤即可重新生成**。

## 部署到 GitHub Pages

仓库根目录已经放了 **`index.html`**（静态托管的默认入口）和 **`.nojekyll`**（跳过 Jekyll 处理），
所以只要开 Pages 就能直接跑：

1. 推到 GitHub
2. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`
3. 分支选 `main`、目录选 `/ (root)`，保存

访问 `https://<用户名>.github.io/<仓库名>/` 即可。`index.html` 是默认文档，
不用在地址里写文件名。

> 如果你的站点根目录不是仓库根（比如要放到 `/nw/` 子路径），把 `index.html` 和 `art/`
> 一起挪进那个子目录即可 —— 生成器用的是相对路径，不受影响。

开启全网榜后记得把 `REMOTE.origins` 填成你的正式域名（见上文）。

## 自检

`index.html` 内置了一套渲染与玩法自检，供无头浏览器读取（纯文本，不依赖截图）：

```
index.html?selftest=1    跑自检，结果写进 <pre id="selftest">
index.html?auto=1&t=300  自动开跑 300 帧（截图用）
```

自检覆盖：贴图加载、图标、键位映射、拖影、跳跃高度与滞空、下蹲判定、
高飞狗「跳不过去 / 蹲得过去」、障碍密度与节奏、昼夜切换，
以及一个会自己玩 4000 帧的简易 AI（用来验证关卡是可通关的）。

用本机 Edge 跑一遍：

```bash
msedge --headless=new --disable-gpu --virtual-time-budget=30000 \
  --dump-dom "file:///path/to/index.html?selftest=1" | grep -oE 'SELFTEST[^<]*'
```
